# 소방안전교육 신청 페이지

GitHub Pages에 올릴 수 있는 휴대폰용 신청 페이지입니다. 사진의 항목에 이메일을 추가했습니다.

**현재 상태: 화면·소스 완성, 응답 저장소 미연결.** GitHub Pages 게시 상태는 저장소의 Settings → Pages에서 확인하세요. 응답 저장소 연결과 시험 접수 확인 후 QR을 배포하세요.

## 구성

- 신청자: 사번·이름 입력 → 소속·이메일·참여 시간 입력 → 동의 → 신청 완료
- 관리자: 이메일·비밀번호 로그인 → 교육별 명단 조회 → 엑셀(.xlsx) 내려받기
- 재사용: 접수 마감, 다음 교육 만들기, 접수 열기. 같은 사이트 주소/QR 유지
- 동일 교육의 사번 중복 신청 차단. 통신 재시도는 동일 요청을 재저장하지 않음
- 신청 일시 = 서버에 접수된 날짜·시간. 화면과 엑셀은 한국 시간
- 사번·이름은 직접 입력하는 정보이며 본인 인증 또는 교직원 명단 검증이 아님
- 신청 변경·취소·출석 체크·자동 이메일 발송은 포함하지 않음. 이메일은 명단에만 저장

## 처음 한 번 설정

사이트는 GitHub Pages, 신청 명단은 별도 Supabase 프로젝트에 보관합니다. 응답·관리자 비밀번호·비밀키는 GitHub에 올리지 않습니다. Supabase는 별도의 서비스이며 학교에서 사용할 수 있는 저장소인지 담당 부서가 확인한 후 연결하세요.

### 1. 신청 저장소 만들기

1. [Supabase](https://supabase.com/)에서 본인 계정으로 새 프로젝트를 만듭니다.
2. SQL Editor에 `database/setup.sql` 전체를 붙여 넣고 한 번 실행합니다. 기존 업무용 DB가 아닌 새 프로젝트에서 실행하세요.
3. Authentication → Users에서 관리자 계정을 만듭니다. 비밀번호는 본인이 설정하고 채팅에 보내지 마세요. 일반 신청자는 Supabase 계정이 필요 없습니다.
4. 만들어진 관리자 사용자의 UUID를 확인하고 SQL Editor에서 다음을 실행합니다.

```sql
insert into public.training_admins(user_id)
values ('관리자 사용자 UUID를 여기에 붙여넣기');
```

5. 관리자 전용 서비스입니다. Authentication 설정에서 일반인의 신규 가입을 비활성화합니다. 관리자 추가는 관리 콘솔에서 진행합니다.
6. 프로젝트의 공개 URL과 **publishable key**를 `site/config.js`에 넣습니다. `service_role`, `sb_secret_...`, DB 비밀번호는 절대 넣지 않습니다. 공개 키만으로 신청 명단을 읽을 수 없도록 DB 권한을 분리했습니다.
7. 접수 초안이 하나 생성되지만 닫힌 상태입니다. `trainings` 테이블의 `privacy_notice`에 실제 수집 부서·문의처·보유 기간을 확정한 안내를 작성합니다. 이후 관리자 화면에서 접수를 열 수 있습니다. 새 교육을 작성해 사용해도 됩니다.

공개 키는 사이트에 표시되어도 되는 식별 키입니다. 공개 이용자는 현재 열려 있는 교육 안내와 신청 함수만 사용할 수 있습니다. 명단 조회는 로그인한 관리자에 한정되며, 관리자 지정 표 자체는 일반 API로 접근할 수 없습니다. 모든 신청 입력 검증·사번 중복 검사는 서버에서도 수행합니다.

### 2. GitHub에 게시

1. GitHub 아이디 `leg2900-arch`로 로그인합니다.
2. 새 저장소 이름을 `fire-safety`로 만듭니다. 다른 이름을 사용하면 `site/config.js`의 `siteUrl`도 바꿉니다.
3. 이 폴더의 **내용 전체**를 저장소 최상위에 올립니다. `site`, `database`, `.github`, `README.md`가 최상위에 있어야 합니다. 압축파일 자체를 올리지 마세요. 웹 업로드 시 `.github/workflows/pages.yml`도 빠지지 않게 확인하세요.
4. 저장소 Settings → Pages → Source에서 **GitHub Actions**를 선택합니다.
5. Actions의 `Publish training page`가 완료되면 Pages에서 실제 게시 주소를 확인합니다. 필요하면 Actions → Run workflow를 실행합니다.
6. `site/config.js`의 `siteUrl`을 확인한 실제 주소로 맞춥니다.

위 계정과 저장소 이름을 사용했을 때 예상 주소는 아래와 같습니다. **현재 게시를 확인한 주소가 아닙니다.**

```text
신청자: https://leg2900-arch.github.io/fire-safety/
관리자: https://leg2900-arch.github.io/fire-safety/admin.html
```

GitHub Pages는 정적인 사이트를 게시합니다. 실제 명단 저장은 Supabase가 담당합니다. 배포 파일에는 `site/`만 포함됩니다.

### 3. 실제 접수와 QR

1. `admin.html`에서 등록한 관리자 계정으로 로그인합니다.
2. 날짜·시간·개인정보 안내를 확인한 뒤 접수를 엽니다. 동시에 한 교육만 열 수 있습니다.
3. 관리자 화면의 QR 영역에 **실제 게시 주소**를 입력하고 QR 만들기 → QR 이미지 저장을 누릅니다. QR은 GIF 이미지이며 인쇄할 수 있습니다.
4. 휴대폰으로 QR을 스캔해 실제 시험 신청 1건을 접수합니다.
5. 관리자 명단에 기록되는지 확인하고 엑셀을 내려받아 확인합니다. 시험 신청은 Supabase에서 담당자가 지울 수 있습니다.

## 다음 교육에 재사용

관리자 화면에서 현재 교육 마감 → 새 교육의 제목·날짜·시간·개인정보 안내 작성 → 새 교육 만들기 → 해당 교육 접수 열기. 사이트 주소를 바꾸지 않으면 기존 QR도 그대로 사용할 수 있습니다. 이전 교육 명단은 선택해서 조회·엑셀 출력할 수 있습니다.

기존에 신청이 있는 교육의 시간 목록을 바꾸기보다 새 교육을 생성하세요. 관리자 페이지는 기존 교육 내용을 직접 수정하지 않고 새 교육을 생성하도록 구성했습니다.

## 엑셀 열

번호 / 교육명 / 교육 일자 / 이름 / 사번 / 소속 / 이메일 / 참여 시간 / 신청 일시(한국 시간) / 개인정보 동의

사번은 텍스트로 내보내므로 앞자리 0을 보존합니다. 입력된 문자열을 수식으로 만들지 않습니다. 조회 시 1,000건 단위로 페이지를 반복해 전체 명단을 가져옵니다. 접수를 마감하고 새로고침한 뒤 내보내면 최종 명단을 정리하기 편합니다.

## 미리보기

`site/index.html?demo=1`과 `site/admin.html?demo=1`은 미리보기입니다. 웹서버에서 열어 사용하세요. 신청 입력을 저장하거나 전송하지 않고, 관리자 화면은 가상 명단 1건만 표시합니다. 실제 관리자 로그인 우회 기능이 아닙니다. 일반 주소에서 저장소 설정이 없으면 신청을 받지 않습니다.

## 운영 참고

- 신청 명단은 GitHub·브라우저 저장소에 남기지 않습니다. 관리자 로그인 토큰은 현재 페이지의 메모리만 사용하며 새로고침 시 다시 로그인해야 합니다.
- 보유 기간은 학교의 확정된 기준으로 안내하세요. 자동 삭제는 포함하지 않았으므로 기간 종료 후 담당자가 Supabase에서 삭제해야 합니다. 개인정보 동의 당시의 안내문도 접수 기록에 함께 보관됩니다.
- QR은 링크 접속 수단입니다. 사번·이름만 입력하는 방식은 신원 검증이 아니므로 타인 정보를 대신 입력하는 것을 기술적으로 막지는 않습니다.
- 정원·대기자·메일 발송·고급 봇 차단은 없습니다. 같은 사번 신청 변경은 담당자가 기존 신청을 확인해 처리합니다.
- 이메일은 형식만 확인하며 `ajou.ac.kr` 도메인만 강제하지 않습니다. 계정 소유 검증/인증메일은 없습니다.
- 서버 시각은 Supabase 기준이며 DB에는 시간대 정보와 함께 저장합니다.
- 글꼴은 Google Fonts를 사용하며 연결되지 않으면 기기의 기본 글꼴로 표시합니다. QR·엑셀 라이브러리는 사이트에 동봉했습니다.

## 검증 범위

휴대폰 크기 브라우저에서 정보 입력 → 신청 항목 → 예시 완료 화면을 확인했습니다. 관리자 예시 명단의 엑셀 내려받기와 QR 생성을 확인했습니다. 실제 Supabase 프로젝트·관리자 인증·DB 권한·실제 인터넷 QR 접속은 프로젝트 연결 후 위 시험 접수 절차로 최종 확인해야 합니다.
